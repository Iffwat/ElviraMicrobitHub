# MicrobitHub protocol v2 conformance scenarios.
#
# Checked against BOTH:
#   - the Python simulator  (tests/test_firmware_conformance.py)
#   - the firmware logic    (firmware/host, run with Node: hub.ts + protocol.ts)
# so the micro:bit firmware answers exactly like SimTransport.
#
# Every scenario starts with a fresh device declaring the simulator's demo
# cards (M1 M2 S1 A1 D1 D2 T1 T2 B1). Lines:
#   === name      start a scenario
#   > LINE        PC sends LINE
#   >> LINE       PC sends LINE with its checksum appended (*XX)
#   ! ID VALUE    the robot program changes a card (sensor reading, text ...)
#   ~ MS          time passes (sensor streaming and the watchdog run)
#   < LINE        expected reply. After each action, the replies must match the
#                 '<' lines that follow it exactly, in order. {any} matches anything.

=== handshake and card sync
> HELLO:2
< HELLO:2,{any}
> SYNC
< CARD:M1,MOTOR,0,-255,255,Left wheel
< CARD:M2,MOTOR,0,-255,255,Right wheel
< CARD:S1,SERVO,90,20,160,Gripper
< CARD:A1,ANALOG_IN,0,0,1023,Light sensor
< CARD:D1,DIGITAL_IN,0,0,1,Bumper
< CARD:D2,DIGITAL_OUT,0,0,1,Headlight
< CARD:T1,TEXT_IN,,,,Status
< CARD:T2,TEXT_OUT,,,,Message
< CARD:B1,SOUND,,,,Alarm
< SYNCED:9

=== heartbeat echo, lower-case tag accepted
> HB:17
< HB:17
> hb:5
< HB:5
